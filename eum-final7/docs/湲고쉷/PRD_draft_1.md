# PRD: EPS 외국인근로자 사업장 변경 도우미 (가칭)

- 작성일: 2026-08-10
- 작성: [팀명 기입]
- 대회: 멋쟁이사자처럼 x Campus AX-Ton (고용노동부 '미래내일일경험' 사업)
- 문서 상태: 초안 (v0.2) — 공지사항 요약 게시판/AI Q&A, 스폰서십 모델 반영 · 인터뷰 결과는 아직 미반영

---

## 1. 개요

고용허가제(EPS)로 국내에서 일하는 외국인근로자가 사업장 변경 절차·기한·허용 사유를 언어장벽 없이 이해하고, 기한을 놓쳐 체류·취업에 불이익을 받지 않도록 돕는 다국어 AI 서비스. 생성형 AI(RAG 챗봇 + 문서 판별)를 활용해 정보 비대칭을 줄이는 것이 핵심 가치다.

---

## 2. 문제 정의

- EPS 외국인근로자는 퇴사 후 1개월 이내 사업장 변경 신청, 신청 후 3개월 내 재취업 실패 시 출국이라는 엄격한 기한 규정을 따라야 한다.
- 사업장 변경은 법정 사유에 해당할 때 최초 3년간 3회, 재고용 기간 2회로 제한된다(근로자 책임이 아닌 부당처우 사유는 예외).
- 대상자는 한국어 문해력이 낮고 다양한 모국어를 쓰며, 절차 정보를 동료·SNS 등 비공식 경로로 얻는 경우가 많아 오정보에 노출되기 쉽다.
- EPS(eps.go.kr), 하이코리아, 1345 등 공식 채널이 있지만 언어·문해력 장벽으로 실효성이 떨어지고, 이 부분의 정보 격차가 실제 체류·취업 불이익으로 이어진다.

> 참고: 1개월/3개월 기한 및 3회/2회 횟수 제한은 팀에서 공식 채널로 최종 확인 완료.

## 3. 타겟 사용자

| 구분 | 설명 | 니즈 |
|---|---|---|
| 1차 사용자 | EPS 외국인근로자 (E-9 등), 원주 인근 산업단지 근무자 중심 | 모국어로 빠르게 절차 확인, 기한 놓치지 않기, 내 상황이 법정 사유에 해당하는지 판단 |
| 2차 사용자 | 이주노동자지원센터·고용센터 실무자 | 상담 부담 경감, 정확한 정보 전달 보조 도구 |
| 확장 이해관계자 | 고용노동부 / HRD코리아 (EPS·하이코리아 운영기관) | 정책 정보 전달 채널 다변화, 민원 감소 |

*(5명 인터뷰: 당사자 3 + 실무자 2, 결과는 본 문서에 v0.2에서 반영 예정)*

## 4. 목표 및 성공 지표 (해커톤 MVP 기준)

| 목표 | 지표(예시) |
|---|---|
| 정보 접근성 개선 | 언어 선택 없이 첫 진입 시 정답 언어로 표시되는 비율(자동감지 정확도) |
| 기한 인지 개선 | D-day 기능 사용 후 "마감일을 알게 됐다"는 사용자 응답 비율 |
| 신뢰도 확보 | 챗봇 답변에 출처(조문/최종확인일) 노출률 100% |
| 데모 완성도 | 4대 핵심 기능이 실제 기기(모바일)에서 끊김 없이 시연 가능 |

해커톤 단계에서는 실사용 지표보다 **문제-솔루션 적합성을 인터뷰와 데모로 증명**하는 것이 우선순위.

## 5. 범위

### MVP에 포함 (In Scope)
1. 공지사항 요약 게시판 + AI Q&A (챗봇 엔진 공유) — 공식 공지/공문 수집·번역·요약 게시, 댓글로 질문하면 AI가 초안 답변
2. 자동 언어 감지 + 원탭 언어 전환
3. 퇴사일 기반 D-day 계산 (신청 마감 / 구직 마감)
4. 서류(계약서·통지서) 사진 업로드 → 법정 사유 해당 가능성 자가진단

> 기존에 별도 기능으로 구상했던 "1:1 챗봇"은 위 1번 게시판의 질의응답 엔진으로 통합 운영한다 (중복 개발 방지).

### 이번 단계에서 제외 (Out of Scope)
- 실제 법률 자문/대리 신청 기능 (정보 안내로 한정)
- 회원가입/로그인 기반 개인화 (익명 사용 우선, 알림만 최소 연락처 수집)
- 이메일/SMS 자동 발송 인프라 고도화 (데모는 화면 배너 강조로 대체 가능)
- 벡터DB 기반 대규모 지식베이스 (JSON 기반 RAG-lite로 시작)
- 고용노동부/HRD코리아와의 공식 연동 (로드맵 상 향후 단계)
- 완전 자동화된 실시간 스크래핑 파이프라인 (MVP는 소수 샘플 공지를 수동/반자동으로 등록, 자동화는 확장 단계)
- 개방형 광고 마켓플레이스 (초기에는 소수의 검증된 스폰서만 수동 계약)

## 6. 핵심 기능 명세

### 6.1 공지사항 요약 게시판 + AI Q&A (통합형 정보 허브)
- **User Story**: 외국인근로자로서, 길고 어려운 공식 공문을 다 읽지 않아도 핵심만 내 언어로 알고 싶고, 궁금한 점은 바로 물어서 근거 있는 답을 받고 싶다.
- **요구사항 — 게시판(요약)**
  - 공식 채널(EPS, 하이코리아, 고용노동부 공지, 가능하면 공공데이터포털 API 우선 활용, 어려운 경우 스크래핑은 이용약관·robots.txt 확인 후 진행)의 공문을 수집
  - LLM으로 번역 + "정말 필요한 내용" 중심 요약 게시 (원문 링크와 출처·게시일 병기)
  - MVP 단계에서는 실시간 자동 수집 대신, 팀이 선별한 샘플 공지 다수를 반자동으로 등록해도 무방
- **요구사항 — 댓글 Q&A**
  - 각 게시글 아래 댓글로 질문 작성 가능 (예: "저도 이 경우에 해당하나요?")
  - 큐레이션된 법령/공지 지식베이스(JSON)를 근거로 AI가 초안 답변 생성, 답변에는 반드시 출처(조문·공지 번호, 최종 확인일) 표시
  - 신뢰도가 낮거나 민감한 사유 판단이 필요한 질문은 "지원센터 실무자 검수 후 게시" 플래그를 달아 사람이 확인한 뒤 공개
  - 지식베이스에 없는 질문은 추측 답변 대신 공식 채널 안내로 회피(hallucination 방지)
  - 답변 말미에 "참고용 정보이며 최종 확인은 관할 고용센터/외국인종합안내센터(1345)에서" 문구 고정 노출
- **완료 기준(AC)**: 샘플 공지 게시물 다수 + 사전 정의한 테스트 질문 세트(예: 10개)에 대해 오류 없는 답변, 출처 표기율 100%, 검수 플래그 동작 확인

> 별도의 "1:1 챗봇" UI를 추가로 만들 필요는 없다 — 동일한 RAG 엔진을 게시판 댓글 Q&A에 재사용해 개발 중복을 줄인다. 자유 질문형 챗봇 창구가 필요하면 같은 엔진 위에 얇은 인터페이스만 얹으면 된다.

### 6.2 자동 언어 감지
- **User Story**: 사용자로서, 언어를 따로 설정하지 않아도 내 폰 언어로 서비스가 바로 열리길 원한다.
- **요구사항**
  - `navigator.language`(클라이언트) / `Accept-Language`(서버)로 최초 언어 결정
  - 지원 언어(1차): 한국어, 영어, 베트남어, 태국어, 캄보디아어, 인도네시아어, 필리핀어, 미얀마어, 네팔어 (미지원 언어는 영어 폴백)
  - 상단 고정 위치에 언어 전환 UI 상시 노출
  - UI 고정 텍스트는 사전 번역 리소스, 챗봇 응답은 실시간 생성 + 핵심 법률 용어는 검수된 고정 문구 사용
- **완료 기준(AC)**: 지원 언어 기기에서 추가 조작 없이 해당 언어로 최초 화면 렌더링

### 6.3 D-day 계산 및 알림
- **User Story**: 퇴사한 근로자로서, 신청 기한과 구직 기한이 각각 며칠 남았는지 한눈에 보고 싶다.
- **요구사항**
  - 퇴사일 입력 → "신청 마감(퇴사+1개월)", "구직 마감(신청+3개월)" 자동 계산
  - 마감 임박(7일/3일/1일 전) 시각적 강조 (색상 변화 등)
  - (확장) 이메일/알림 발송은 서버리스 cron으로 설계, MVP 데모에서는 화면 강조로 대체 가능
- **완료 기준(AC)**: 임의의 퇴사일 입력 시 두 D-day가 정확히 계산되어 표시

### 6.4 서류 자가진단
- **User Story**: 부당한 대우를 받았다고 느끼는 근로자로서, 내 상황이 법정 사유에 해당하는지 서류를 올려 확인받고 싶다.
- **요구사항**
  - 계약서/통지서 이미지를 LLM 비전 기능으로 판독
  - 지식베이스의 법정 사유 항목과 대조해 "해당 가능성" 판단 결과 제공
  - 결과는 확정 판단이 아닌 "가능성 안내 + 상담 권유" 톤으로 고정
- **완료 기준(AC)**: 샘플 서류(정상/사유 해당 의심 각 2건 이상)에 대해 방향성 있는 결과 출력, 확정적 법률 판단 문구 없음

## 7. 비기능 요구사항

- **정확성/최신성**: 법령 인용 시 조문·개정일 명시, 정기적(예: 격주) 공식 채널 모니터링으로 지식베이스 갱신
- **개인정보 최소화**: 이름 등 식별정보 대신 익명 세션 기반으로 D-day만 저장, 알림용 연락처는 선택 입력
- **접근성**: 모바일 퍼스트, 저사양 기기·저속 네트워크 고려한 경량 UI
- **면책/신뢰성**: 모든 답변/판단 결과에 "정보 안내이며 법률 자문 아님" 고지 고정 노출
- **다국어 품질**: 핵심 법률 용어(사업장 변경, 출국, 재고용 등)는 전문 검수 고정 번역 사용

## 8. 차별화 포인트

- 기존 공식 채널(EPS, 하이코리아, 1345) 대비 "언어장벽 없이, 개인 상황에 맞춰, 더 쉽게" 전달
- 어려운 공문을 요약·번역해 게시판으로 축적하고 공개 Q&A로 반복 상담 부담을 줄이며 신뢰도를 쌓음
- 언어 설정 절차 자체를 없앤 자동 감지 UX
- 절차 안내에 그치지 않고 서류 기반 개인화 판단(자가진단) 제공
- 원주 지역 산업단지 현황 및 지역 이주노동자지원센터 연계로 지역문제 해결 관점 확보 [팀에서 리서치 반영 예정]

## 9. 기술 스택 및 아키텍처 개요

- 프론트엔드: Next.js(App Router) + TypeScript + Tailwind CSS
- 백엔드: Next.js API Routes
- LLM: Claude API (텍스트 챗봇 + 비전 기반 서류 판독)
- 지식베이스: JSON 기반 RAG-lite (벡터DB 미사용, 확장 시 Supabase pgvector 검토)
- 데이터 수집: 공공데이터포털(data.go.kr) API 우선 확인 → 없는 항목은 팀 선별 수동/반자동 등록 → (확장) 이용약관 확인된 범위 내 스크래핑 자동화
- 데이터 저장: Supabase(Postgres) — 최소 정보만(세션, D-day, 게시글/댓글, 선택적 연락처)
- 배포: Vercel

*(상세 구현 프롬프트는 별도 `dev_prompt_guide.md` 참고)*

## 11. 비즈니스 모델 및 확장 전략

1. **1단계 (해커톤~초기)**: 무료 공개 서비스로 시작, 이주노동자지원센터 현장 검증. 최소 운영비는 소수의 **검증된 스폰서십**(공인 어학원, 정식 등록 송금업체, 인증받은 우수 사업장 등)으로 충당하며, 스폰서 콘텐츠는 정보와 명확히 구분 표시하고 일자리 알선처럼 보이는 광고는 배제
2. **2단계 (검증 후)**: 고용노동부·HRD코리아(EPS/하이코리아 운영기관)와 연계 논의, 지역 고용센터 공식 안내 채널 확보
3. **3단계 (확장)**: B2G 형태로 공식 채널(EPS/하이코리아)에 임베드되거나 위탁 운영 형태로 지속가능한 운영 재원 확보

> 해커톤 발표에서는 2~3단계를 "로드맵"으로 제시하고, 데모는 1단계(사용자 관점 완결성)에 집중. 스폰서십과 B2G를 동시에 강조하면 메시지가 흐려질 수 있으므로 "초기 최소 운영비는 검증된 스폰서 → 이후 공공기관 연계로 전환"하는 하나의 흐름으로 설명한다.
