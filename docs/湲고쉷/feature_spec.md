# 기능 정의서 (Functional Specification)

- 대상 서비스: EPS 외국인근로자 사업장 변경 도우미 (가칭)
- 연관 문서: `PRD_draft.md` (v0.2), `dev_prompt_guide.md`
- 버전: v0.1
- 작성일: 2026-08-13

---

## 0. 문서 목적

PRD가 "왜 만드는가/무엇을 목표로 하는가"를 다룬다면, 본 문서는 "실제로 어떤 화면에서, 어떤 입력을 받아, 어떤 로직으로 처리해, 무엇을 출력하는가"를 개발 가능한 단위로 정의한다. Claude Code 등으로 개발 시 기능 단위 작업 분배와 QA 체크리스트로 그대로 활용 가능하도록 구성했다.

| ID | 카테고리 | 기능명 | 우선순위 | 관련 화면 |
|---|---|---|---|---|
| FT-01 | 공통 | 자동 언어 감지 및 전환 | Must | 전체 화면 공통 |
| FT-02 | 게시판 | 공지 요약 게시글 목록/조회 | Must | 홈/게시판 |
| FT-03 | 게시판 | 공지 원문 수집·번역·요약 등록 | Must | 관리자/배치 |
| FT-04 | 게시판 | 댓글(질문) 작성 | Must | 게시글 상세 |
| FT-05 | AI 엔진 | RAG 기반 AI 답변 생성 | Must | 게시글 상세(댓글) |

| FT-08 | D-day | 마감 임박 알림 | Should | D-day 대시보드 |
| FT-09 | 자가진단 | 서류 이미지 업로드 | Must | 서류 자가진단 |
| FT-10 | 자가진단 | LLM 비전 기반 사유 판별 | Must | 서류 자가진단 |
| FT-11 | 공통 | 출처·면책 문구 표시 컴포넌트 | Must | 전체 화면 공통 |
| FT-12 | 공통 | 스폰서/광고 영역 (검증된 파트너) | Could | 홈/게시판 하단 |

우선순위 기준: **Must**=해커톤 데모 필수, **Should**=시간 되면 포함, **Could**=로드맵/확장 단계.

## 2. 정보 구조 (화면 목록)

1. 홈 / 게시판 목록 — 요약된 공지 카드 리스트 (최신순)
2. 게시글 상세 — 원문 요약 + 출처 + 댓글(질문) 스레드
3. D-day 대시보드 — 퇴사일 입력 폼 + 두 개의 D-day 카드(신청 마감/구직 마감)
4. 서류 자가진단 — 이미지 업로드 + 판별 결과 카드
5. 언어 설정(전역 헤더) — 감지된 언어 표시 + 변경 드롭다운
6. (Should) 관리자 페이지 — 검수 대기 댓글 목록, 승인/반려

## 3. 기능 상세 정의

### FT-01. 자동 언어 감지 및 전환
| 항목 | 내용 |
|---|---|
| 설명 | 최초 접속 시 사용자가 언어를 선택하지 않아도 기기 언어로 UI 표시 |
| 입력 | `navigator.language`(클라이언트), `Accept-Language` 헤더(서버) |
| 처리 로직 | 감지된 언어 코드가 지원 목록(ko/en/vi/th/km/id/tl/my/ne)에 있으면 해당 언어 적용, 없으면 en 폴백. 이후 사용자가 헤더에서 직접 바꾸면 세션에 우선 저장 |
| 출력 | 페이지 전체 UI 텍스트 및 챗봇 응답 언어 |
| 예외처리 | 언어 감지 실패(값 없음) 시 en 기본 적용 |
| 비고 | UI 고정 텍스트는 `/messages/{locale}.json`, AI 응답은 실시간 생성 |

### FT-02. 공지 요약 게시글 목록/조회
| 항목 | 내용 |
|---|---|
| 설명 | 수집된 공식 공지를 요약·번역된 카드 형태로 목록/상세 제공 |
| 입력 | 없음(조회), 상세 진입 시 postId |
| 처리 로직 | DB에서 게시글 최신순 조회, 감지된 언어의 번역본 우선 표시(없으면 실시간 번역 생성 후 캐시) |
| 출력 | 제목, 요약, 출처 링크, 게시일, 최종확인일 |
| 예외처리 | 번역본 없을 시 로딩 상태 후 생성, 실패 시 원문(한국어) + 안내 문구 표시 |

### FT-03. 공지 원문 수집·번역·요약 등록
| 항목 | 내용 |
|---|---|
| 설명 | 공식 채널의 공지/공문을 수집해 게시글로 등록 |
| 입력 | 원문 URL 또는 원문 텍스트(수동 입력 가능) |
| 처리 로직 | 1) 공공데이터포털 API 확인 → 2) 없으면 팀이 선별한 원문 수동 등록 → 3) LLM으로 요약·번역 생성 → 4) 조문/공지번호·출처·최종확인일 메타데이터 저장 |
| 출력 | 게시글 레코드(원문 링크 포함) |
| 예외처리 | 자동 수집 실패 시 관리자에게 수동 등록 안내 |
| 비고 | MVP는 완전 자동화 대신 반자동(팀 선별 + 버튼 클릭 요약)으로 시작 가능 |

### FT-04. 댓글(질문) 작성
| 항목 | 내용 |
|---|---|
| 설명 | 게시글 하단에서 사용자가 자유 텍스트로 질문 작성 |
| 입력 | 텍스트(감지된 언어), 연결된 postId |
| 처리 로직 | 질문 저장 → FT-05 AI 답변 생성 트리거 |
| 출력 | 댓글 목록에 질문 추가 |
| 예외처리 | 빈 입력/과도한 길이 제한(예: 500자) 유효성 검사 |

### FT-05. RAG 기반 AI 답변 생성
| 항목 | 내용 |
|---|---|
| 설명 | 질문에 대해 지식베이스 근거로 AI가 답변 초안 생성 |
| 입력 | 질문 텍스트, 감지된 언어, 관련 게시글 컨텍스트 |
| 처리 로직 | knowledge-base.json에서 관련 항목 매칭(키워드 또는 임베딩 유사도) → 시스템 프롬프트에 주입 → Claude API 호출 → 답변에 출처(조문/공지 번호, 최종확인일) 포함하도록 강제 |
| 출력 | AI 답변 텍스트 + 출처 배열 + 신뢰도 플래그 |
| 예외처리 | 지식베이스에 근거 없음 → "확인 불가, 공식 채널(1345/고용센터) 안내"로 대체, 추측 답변 금지 |
| 비고 | 모든 답변 하단에 FT-11 면책 문구 고정 삽입 |

### FT-06. 실무자 검수 플래그 및 게시 승인 (Should)
| 항목 | 내용 |
|---|---|
| 설명 | 신뢰도가 낮거나 민감한 답변은 자동 공개하지 않고 검수 대기 상태로 전환 |
| 입력 | FT-05의 신뢰도 플래그 |
| 처리 로직 | 신뢰도 임계값 미달 시 `pending` 상태로 저장, 관리자 승인 시 `published`로 전환 |
| 출력 | 관리자 페이지의 검수 대기 목록, 승인/반려 액션 |
| 예외처리 | 일정 시간 미검수 시 알림(선택) |

### FT-07. 퇴사일 입력 및 D-day 계산
| 항목 | 내용 |
|---|---|
| 설명 | 퇴사일을 입력하면 신청 마감/구직 마감 D-day 자동 계산 |
| 입력 | 퇴사일(date) |
| 처리 로직 | 신청마감 = 퇴사일 + 1개월, 구직마감 = 신청일(또는 신청마감) + 3개월 (팀 확인 기준값 적용, 상수로 분리 관리) |
| 출력 | 두 개의 D-day 카드(D-n, 날짜) |
| 예외처리 | 미래 날짜 입력 등 비정상 입력 값 검증, 이미 지난 마감일은 경고 색상 표시 |

### FT-08. 마감 임박 알림 (Should)
| 항목 | 내용 |
|---|---|
| 설명 | 마감 7일/3일/1일 전 사용자에게 알림 |
| 입력 | 저장된 D-day 레코드, (선택) 연락처 |
| 처리 로직 | 서버리스 cron이 매일 배치로 임박 대상 조회 후 알림 발송(또는 MVP는 화면 배너 강조로 대체) |
| 출력 | 이메일/화면 알림 |
| 예외처리 | 연락처 미입력 시 화면 알림만 제공 |

### FT-09. 서류 이미지 업로드
| 항목 | 내용 |
|---|---|
| 설명 | 계약서·통지서 등 사진을 업로드 |
| 입력 | 이미지 파일(jpg/png), 최대 용량 제한 |
| 처리 로직 | 업로드 파일 임시 저장 → FT-10 트리거 |
| 출력 | 업로드 완료 상태, 판별 대기 표시 |
| 예외처리 | 지원하지 않는 형식/용량 초과 시 에러 메시지 |

### FT-10. LLM 비전 기반 사유 판별
| 항목 | 내용 |
|---|---|
| 설명 | 업로드된 서류를 읽고 법정 사유 해당 가능성 안내 |
| 입력 | 이미지, 지식베이스의 "법정 사유" 항목 |
| 처리 로직 | Claude API 비전 기능으로 텍스트 추출 및 해석 → 지식베이스 사유 목록과 대조 → "가능성 있음/판단 어려움" 등 톤으로 결과 생성 |
| 출력 | 판별 결과 카드(가능성 안내 + 상담 권유 문구 고정 포함) |
| 예외처리 | 이미지 인식 실패/판독 불가 시 "직접 확인이 어려우니 지원센터 상담 권장" 안내로 대체, 확정적 법률 판단 문구 금지 |

### FT-11. 출처·면책 문구 표시 (공통)
| 항목 | 내용 |
|---|---|
| 설명 | 모든 AI 응답/판별 결과에 출처와 면책 문구를 표준화된 형태로 노출 |
| 입력 | 없음(공통 컴포넌트) |
| 처리 로직 | 답변 렌더링 시 하단에 고정 컴포넌트 삽입 |
| 출력 | "이 정보는 참고용이며, 최종 확인은 관할 고용센터 또는 외국인종합안내센터(1345)에서 확인하세요" + 조문/공지 출처, 최종확인일 |
| 비고 | 문구는 다국어 리소스로 관리, 임의 수정 금지(고정 문구) |

### FT-12. 스폰서/광고 영역 (Could)
| 항목 | 내용 |
|---|---|
| 설명 | 검증된 파트너(공인 어학원, 정식 등록 송금업체 등)의 콘텐츠 노출 |
| 입력 | 관리자가 등록한 스폰서 콘텐츠 |
| 처리 로직 | 정보 영역과 시각적으로 분리된 위치에 "광고" 라벨과 함께 노출 |
| 출력 | 스폰서 배너/카드 |
| 예외처리 | 일자리 알선형 문구 포함 여부 사전 검수(수동) |

## 6. 참고 — 검증 필요 상수 (Open)

- 신청 마감 = 퇴사일 + 1개월 (팀 확인 완료 기준값, `dev_prompt_guide.md` 참고)
- 구직 마감 = 신청 후 + 3개월 (팀 확인 완료 기준값)
- 사업장 변경 횟수 제한: 최초 3년 3회 / 재고용기간 2회 (부당처우 등 근로자 책임 아닌 사유는 예외)

> 지식베이스에 반영하기 전 최종 문구는 하이코리아·EPS 공식 채널 기준으로 한 번 더 대조 권장.
